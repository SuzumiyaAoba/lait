# ツール周回の要約による圧縮（default.compaction）

[ドキュメント目次に戻る](./README.md)

MCP・サブエージェント・カスタムシェルツールの tool loop([MCP サーバーのツールを使う](./mcp.md)
参照)は、ラウンドを重ねるたびにメッセージ履歴(モデルのツール呼び出し + ツール実行結果)が
積み上がっていきます。`max_tool_rounds`(既定 8)に達する前に、接続先モデルの**コンテキスト
ウィンドウ/トークン上限**(lait 自身の制限ではなく、接続先プロバイダー側の制限)に達して
エラーになることがあります。`default.compaction:` は、一定ラウンドごとにモデル自身へ「ここまでの
会話を要約して」と依頼し、古いラウンドを要約1件に置き換えることで、この履歴の増大を抑えます。

## 使い方

```yaml
# lait.config.yml
default:
  compaction:
    trigger_rounds: 6   # 必須。この倍数ラウンドの直前で要約する
    keep_last_n: 4      # 省略可(既定4)。直近何件のメッセージをそのまま残すか
```

- `lait.config.yml` の `default:` にのみ指定できます(CLI フラグ・agent frontmatter・
  ワークフローノード個別の上書きは今のところありません)。
- `trigger_rounds` はラウンド数の倍数(`round % trigger_rounds == 0`)ごとに、そのラウンドの
  リクエストを送る**前**に圧縮します。1以上の整数である必要があります(`0` は設定エラー)。
- `keep_last_n` は、先頭のシステムメッセージ(あれば無条件に残ります)を除いた、直近何件の
  メッセージをそのまま残すかです。残りのメッセージ数が `keep_last_n` 以下の場合、まだ圧縮する
  意味がないため何もしません。

## 動作の仕組み

1. 対象ラウンドのリクエストを送る前に、これまでの会話履歴 + 「ここまでの会話を要約してください」
   という指示を1回だけモデルへ送信します。
2. 返ってきた要約テキストを1件の assistant メッセージとして、先頭のシステムメッセージ(あれば)の
   直後、`keep_last_n` 件の直近メッセージの前に挿入します。
3. 圧縮後の(短くなった)メッセージ履歴で、そのラウンド自身のリクエストを続けて送信します。

要約のためのリクエストも、通常のラウンドと**全く同じ経路**(`--cache`/`--record`/`--replay`/
[実行トレース](./trace.md))を通ります。つまり:

- `--record` で記録したカセットには要約リクエストの分も含まれ、`--replay`/`lait test` で
  再生する際は要約リクエスト用のカセットも必要です。`default.compaction:` を後から有効にした
  場合、既存のカセットには要約リクエストが記録されていないため再記録が必要です。
- [実行トレース](./trace.md)には、要約リクエスト自体の `"chat"` イベントに加えて、
  `"compact"` という専用のイベントが記録されます(`lait.compaction.round`/
  `lait.compaction.messages_before`/`lait.compaction.messages_after` 属性付き)。

## 制限事項

- **`lait run`(ワークフローの `prompt`/`agent` ノード)・`lait agent run`・チャット
  (`--stream` を使わない場合)にのみ適用されます。** `--stream` を使う経路(`lait chat`)では
  今のところ圧縮されません。
- ラウンド数(`trigger_rounds`)ベースのトリガーのみで、トークン数ベースのトリガーは
  今のところありません。
- 要約に使うモデルは常に**そのリクエスト自身のモデル**です。別モデル(より安価・高速なモデル)を
  要約専用に指定するオプションは今のところありません。
- `max_tool_rounds` 自体は伸びません — 圧縮はラウンドあたりのメッセージ量を抑えるだけで、
  ラウンド数の上限そのものを緩和するものではありません。
